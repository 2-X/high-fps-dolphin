ROOT CAUSE of the Mecha Bowser miss
The coaster ride uses a dedicated camera mode, CAMERA_MODE_JET_COASTER,
dispatched to CPolarSubCamera::ctrlJetCoasterCamera_ -- NOT the ordinary
L-button aim camera (ctrlLButtonCamera_) that v2 patched. They are separate
functions with separate stick-Y negates, so v2's fix never reached the fight.

Internal names confirm this is the Mecha Bowser fight, not some unrelated
coaster:
  src/Camera/cameragc.cpp:
    cJetCoasterCam1BckName  = "tinkoopa_camera";        // tinkoopa = Mecha Bowser
    cJetCoasterDemoBckName  = "tinkoopa_killer_camera";
  src/Camera/cameragc.cpp:926  case CAMERA_MODE_JET_COASTER: ctrlJetCoasterCamera_();

Source (decomp, JP tree src/Camera/CameraJetCoaster.cpp:109-118):

The `-mCompSPos[5]` is the exact analogue of v2's ctrlLButtonCamera_
`fneg f30,f0`; both negate the vertical stick before feeding the SHARED
CPolarSubCamera::rotateX_ByStickY_ pitch accumulator. Flipping the negate
in this caller un-inverts the fight aim while leaving rotateX_ByStickY_
(shared) and everything else untouched.

Why a bare 04 write is safe (no C2 gate needed)
ctrlJetCoasterCamera_ is reached ONLY from the CAMERA_MODE_JET_COASTER arm
of the camera dispatch (cameragc.cpp:926). That mode is entered only for the
tinkoopa/pinna2 coaster ride (Mecha Bowser fight). The patched instruction
is additionally inside the isLButtonMode (aiming) sub-branch. It is a
different function from ctrlLButtonCamera_, so it shares no code with the
squat spray, the Y-button first-person look, or the normal orbit camera.
The non-aim else-branch of this function reads mCompSPos[6]/[7] (manual
camera-framing offsets) and is left untouched -- only the active-aim
vertical is flipped, matching v2's philosophy.
