Tank Controls v3 (latched turnaround + grace window)
GMSE01 (US). Supersedes v2 (remove v2 when enabling v3).

v2 problem (user-confirmed): the rear-cone flip re-targeted EVERY frame
(target = face+theta from the CURRENT face), so holding back spun Mario
at full IConverge rate and side-jump direction was effectively random.

v3 semantics (C2 @ 80251ddc, same hook as v2):
  theta = stick angle - 0x8000 (signed s16; 0 = dead ahead of Mario)
  |theta| < 0x6000 (front 270deg): proportional steering as v2
      offset = clamp(theta>>6, +/-0xC0); latch timer cleared.
  |theta| >= 0x6000 (rear cone):
      timer==0 (fresh press): flip ONCE -> intendedYaw = face + theta,
          latch timer = 0x168 (360 frames = 1.0s @ 360fps).
      timer>0 (held / within window): intendedYaw = PREVIOUS
          mIntendedYaw (the latched flip target), timer--.
  So: tap back = one clean 180 (skid/side-jump direction is
  deterministic); holding back keeps running the new heading ("forward,
  directly behind you"); pressing forward inside the window resumes
  normal steering off the new facing. Worst case, holding back a full
  second re-flips once per second instead of spinning.

State storage: TMario+0x92 (halfword). Decomp header names it unk92;
written once in MarioInit (=0x11), never read anywhere in game code —
vestigial. Nonzero init only delays the first-ever rear flip by ~17
frames; any normal-steering frame zeroes it. (If future decomp work
finds a real reader of unk92, relocate the latch.)

TUNING KNOBS:
  window 0x168 (word 38600168) -> grace length; per-frame, scale with G
  steer shift 6 / cap 0xC0 / cone 0x6000 -> as v2
